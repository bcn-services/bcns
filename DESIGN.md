# bcns-data — Design

Implements `REQUIREMENTS.md` (R1–R39). Every table, policy, view, RPC, connector, job, and SB panel is
specified here so the build session makes no design calls. Section 10 maps each requirement to its
section. Section 11 ("Needs Nate") lists what this document could not decide.

Conventions: Postgres 15 on the shared Supabase Pro project. Base tables live in schema **`data`**;
the dashboard-facing contract lives in schema **`api`**; PostgREST exposes **`api` only**. All
timestamps are `timestamptz`; day buckets are `date` in the client's timezone; money is
`amount_minor bigint` + `currency char(3)`. `client_id` is the first column of every primary key,
unique key, and index on tenant data. Names below are final — the build uses them verbatim.

## 0. Design calls made here (not in REQUIREMENTS)

Recorded so the build does not re-decide them. Each is reversible on a concrete failure.

| # | Call | Why |
|---|------|-----|
| D1 | Base tables in schema `data`, not `public`; PostgREST exposed schemas = `api` only. | R13 becomes structural: nothing outside `api` is reachable over HTTP. |
| D2 | Policies compare `client_id = (select data.active_client_id())`. The function reads the JWT claim **and** checks `memberships` + `clients.status = 'active'` once per statement (Postgres InitPlan), not per row. | R2 and R4 hold on the next request, not the next token refresh; cost is one index lookup per query. |
| D3 | The tenant-role claim is named **`client_role`**, not `role`. | Supabase reserves the `role` claim (`authenticated`/`anon`) for PostgREST role switching; overwriting it breaks every request. REQUIREMENTS' `role` is satisfied by `client_role`. |
| D4 | `security_invoker` views require `authenticated` to hold SELECT on the `data` tables they read (RLS still filters). "No grant on base tables" (R13) is read as "no HTTP path to base tables" — enforced by D1 — plus **no grant at all** on `source_tokens`, `connector_schedule`, `connector_runs`, `notifications`. | `security_invoker` is the only view mode that applies the caller's RLS; a `security_definer` view runs as its owner and would bypass RLS. |
| D5 | Raw is append-only. PK `(client_id, source, entity, external_id, fetched_at)`, range-partitioned by month of `fetched_at`. Normalize takes the newest row per `(client_id, source, entity, external_id)` by `(source_updated_at, fetched_at)`. | R6/R7: every fetch is kept, replay is deterministic. |
| D6 | Connector health is **computed by the worker into `data.connector_health`** each tick; `api.connector_health_v1` is a plain view over it. | Dashboards cannot read `connector_schedule`/`connector_runs` (D4), and a per-read scan of runs would not scale. |
| D7 | Non-secret per-source config (shop domain, ad account id, board id, Drive folder id, column ids) lives in `connector_schedule.config jsonb`; `source_tokens` holds secrets only. | One place per concern; tokens table stays minimal and service-role-only. |
| D8 | Meta campaigns and ads are `records` rows (`kind = 'campaign' | 'ad'`) — the "doesn't fit → records" rule. Meta creative images are downloaded into Storage as `media(source='meta')`. | No entity table; Top Creative joins `daily_metrics → records → media`. Meta CDN URLs expire; a local copy makes the panel stable and thumbnails uniform. |
| D9 | Signed URLs are minted client-side by the Storage SDK **after** `api.download_url(media_id)` records the bytes and checks the budget; the Storage SELECT policy is the enforcement (R22). The shared data-client package exposes one `downloadUrl()` that does both. | SQL cannot call the Storage signing endpoint; the policy is the only thing that can deny the object itself. |
| D10 | Thumbnails are generated by the worker (next tick after upload, ≤ 5 min) with `sharp`, 512 px longest edge, JPEG, into `<client_id>/thumb/`. Videos get no thumbnail in v1. | Storage uploads cannot run code; "at upload" (R21) is read as "before the file is browsable". |
| D11 | Worker claims work with `UPDATE … FOR UPDATE SKIP LOCKED` and a 20-minute lease; each run has a 4-minute wall-clock budget and persists its cursor after every page. | R27/R28: a 260-page backfill spans ticks with no state outside the DB; two overlapping ticks cannot double-process; a crashed job's lease expires. |
| D12 | The scheduler's due-index is `(next_run_at) WHERE enabled` **without** `client_id` leading. | It is the one cross-tenant scan in the system and is service-role-only. Every other index leads with `client_id`. |
| D13 | Tokens are stored plaintext in `data.source_tokens` (RLS enabled, zero policies → service role only). | Requirement says "readable only by the service role"; anyone with the backup also has the service key. Supabase Vault is the upgrade if a backup ever leaves Supabase. |
| D14 | bcns alerts go out from the worker via Resend to `BCNS_ALERT_EMAIL`, deduped through `data.notifications.dedupe_key`. | The worker is the only always-running platform code; the pipeline's notify router is a separate repo. |
| D15 | Pooled-egress alert (R23) is computed from `sum(egress_ledger.bytes)` across clients against `EGRESS_ALLOWANCE_BYTES` (env, default 250 GB), not from the Supabase Management API. | No external dependency; the ledger over-counts (requested, not transferred bytes), which is the conservative direction for an 80 % alert. |
| D16 | `owner` may **remove** a member via `api.remove_member`; **adding** a user stays a bcns task (needs the Auth admin API, which needs the service key). | Matches "bcns creates users" while giving `owner` a real power. Invite flow is a later RPC + edge function if a client asks. |
| D17 | Dashboards self-report their version through `api.report_dashboard_version` on boot. | `dashboard_versions` stays correct without a bcns task. |
| D18 | Inventory history is a once-per-local-day snapshot written by the Shopify connector into `daily_metrics(metric='inventory_units')`. | The Overview inventory tile needs a trend line; Shopify exposes only current levels. |
| D19 | Line items, variants, Monday column raw values, Meta `actions` arrays stay in `attributes`/raw, not columns. | R9. No SB panel reads them. |
| D20 | Google access tokens (1 h) are refreshed at run start by the Meet connector itself; the 24 h refresh job (R30) covers any token with an `expires_at`. Shopify custom-app, Monday personal, and Meta system-user tokens do not expire and have no refresh. | Only Google has a refresh flow among SB's sources. |

## 1. Schema `data` — tables

DDL sketch per table: columns, keys, indexes. `…common…` on canonical tables means:

```sql
id                uuid primary key default gen_random_uuid(),
client_id         uuid not null references data.clients(id),
source            data.source not null,
external_id       text not null,
attributes        jsonb not null default '{}'::jsonb,
source_updated_at timestamptz,
created_at        timestamptz not null default now(),
updated_at        timestamptz not null default now(),   -- trigger data.touch_updated_at()
unique (client_id, source, external_id)
```

Types:

```sql
create schema data;  create schema api;
create type data.source        as enum ('shopify','meta','monday','meet','upload','dashboard','platform');
create type data.client_status as enum ('active','paused','churned');
create type data.member_role   as enum ('member','owner');
create type data.token_kind    as enum ('shopify_admin','monday_personal','meta_system_user','google_oauth_refresh');
create type data.token_status  as enum ('active','auth_failed','revoked');
create type data.run_mode      as enum ('backfill','incremental','renormalize');
create type data.run_status    as enum ('running','ok','error','auth_failed');
create type data.health_status as enum ('ok','stale','auth_failed','error','never_ran');
```
`never_ran` is the fifth health value: a schedule row exists but no run has finished. It renders as
"connecting…" and never alerts. It is additive to the REQUIREMENTS enum.

### 1.3 Raw

**`data.raw`** — partitioned by range on `fetched_at`, one partition per calendar month
(`data.raw_2026_09`, …) plus `data.raw_default`. Created by `data.ensure_raw_partitions()` (§5.1).
```sql
client_id          uuid not null,
source             data.source not null,
entity             text not null,          -- 'order','refund','payout','product','inventory_snapshot',
                                           -- 'campaign','ad','insight_campaign_day','insight_ad_day',
```

Retention: forever while `clients.status <> churned`.

### 1.5 Common triggers and helpers

- `data.touch_updated_at()` — `before update` on every table with `updated_at`.
- `data.local_day(ts timestamptz, client uuid) returns date` — `(ts at time zone
  (select timezone from data.clients where id = client))::date`; STABLE. Used by normalize (the
  worker computes `day` itself for bulk inserts; the function is for `renormalize` SQL).
- `data.ensure_raw_partitions()` — creates partitions for the current month through month+2 if
  missing, plus `raw_default`. Idempotent; run every tick.

## 2. Access control

### 2.1 Auth hook (JWT claims)

`public.custom_access_token_hook(event jsonb) returns jsonb` — registered in Supabase Auth →
Hooks → "Customize Access Token". Runs on every token issue/refresh.

```sql
create or replace function public.custom_access_token_hook(event jsonb) returns jsonb
language plpgsql stable security definer set search_path = '' as $$
declare m record; claims jsonb := event->'claims';
begin
  select m.client_id, m.role, c.status into m
  from data.memberships m join data.clients c on c.id = m.client_id
  where m.user_id = (event->>'user_id')::uuid;
  if m is null then
    return jsonb_build_object('error', jsonb_build_object('http_code', 403, 'message', 'no membership'));
  end if;
  if m.status <> 'active' then
    return jsonb_build_object('error', jsonb_build_object('http_code', 403, 'message', 'client ' || m.status));
  end if;
  claims := claims || jsonb_build_object('client_id', m.client_id, 'client_role', m.role);
  return jsonb_set(event, '{claims}', claims);
end $$;
grant usage on schema public, data to supabase_auth_admin;
grant execute on function public.custom_access_token_hook to supabase_auth_admin;
revoke execute on function public.custom_access_token_hook from authenticated, anon, public;
grant select on data.memberships, data.clients to supabase_auth_admin;
-- RLS policies "auth_admin_read" on both tables: to supabase_auth_admin using (true)
```
Denying the token (403) is what disables logins at churn (R34) and on membership removal, at the
next refresh. **JWT expiry is set to 600 s** (Auth → Sessions) so "next refresh" is ≤ 10 min. The
per-request lockout (R4) comes from the policy function in §2.2, which does not depend on the token.

### 2.2 Policy helpers (schema `data`, not exposed)

```sql
create function data.jwt_client_id() returns uuid language sql stable as $$
  select nullif(current_setting('request.jwt.claims', true)::jsonb ->> 'client_id', '')::uuid $$;
create function data.jwt_client_role() returns data.member_role language sql stable as $$
  select nullif(current_setting('request.jwt.claims', true)::jsonb ->> 'client_role', '')::data.member_role $$;

-- The tenant boundary. NULL ⇒ every policy is false ⇒ zero rows.
create function data.active_client_id() returns uuid
language sql stable security definer set search_path = '' as $$
  select m.client_id
  from data.memberships m join data.clients c on c.id = m.client_id
  where m.user_id = auth.uid()
    and m.client_id = data.jwt_client_id()
    and c.status = 'active' $$;
revoke execute on function data.active_client_id from public, anon;
grant execute on function data.active_client_id to authenticated;

create function data.egress_exceeded(client uuid) returns boolean
language sql stable security definer set search_path = '' as $$
  select coalesce(e.bytes, 0) > c.egress_quota_bytes
  from data.clients c
  left join data.egress_ledger e
    on e.client_id = c.id and e.month = date_trunc('month', now() at time zone c.timezone)::date
  where c.id = client $$;
```
Every policy below writes the call as `(select data.active_client_id())` — the subselect makes
Postgres evaluate it once per statement (InitPlan) instead of once per row.

### 2.3 Grants

```sql
revoke all on schema public from anon, authenticated;              -- nothing lives there but the hook
grant usage on schema data to authenticated;                        -- needed by security_invoker views
grant usage on schema api  to authenticated, anon;                  -- anon gets USAGE only, no objects
grant select on data.clients, data.memberships, data.dashboard_versions, data.egress_ledger,
                data.connector_health, data.customers, data.jobs, data.messages, data.money,
                data.media, data.media_sets, data.media_set_items, data.products,
                data.daily_metrics, data.records to authenticated;
-- NO grant to authenticated/anon on: data.source_tokens, data.connector_schedule,
--   data.connector_runs, data.notifications, data.raw (and partitions).
-- No INSERT/UPDATE/DELETE grants on any data table to authenticated: writes go through
--   security definer RPCs (§3.3).
alter default privileges in schema data revoke all on tables from anon, authenticated;
```
PostgREST config (Dashboard → API): **Exposed schemas = `api`**; Extra search path = `api`.
`public` and `graphql_public` are removed. The GraphQL endpoint is disabled.

### 2.4 RLS policies — one block per table

`alter table … enable row level security; alter table … force row level security;` on **every**
table in `data` (including `raw` partitions, `source_tokens`, `connector_schedule`,
`connector_runs`, `notifications` — those have no policies, so only the service role, which
bypasses RLS, can touch them). CI test `rls_every_table` (§7) fails otherwise.

Shorthand: `T` = `(select data.active_client_id())`, `W` = `data.jwt_client_role() in ('member','owner')`.

| Table | SELECT | INSERT | UPDATE | DELETE |
|---|---|---|---|---|
| `clients` | `id = T` | — | — | — |
| `memberships` | `client_id = T` | — | — | — (owner removal via RPC) |
| `dashboard_versions` | `client_id = T` | — (RPC) | — (RPC) | — |
| `egress_ledger` | `client_id = T` | — | — | — |
| `connector_health` | `client_id = T` | — | — | — |
| `customers`, `jobs`, `messages`, `money`, `products`, `daily_metrics` | `client_id = T` | — | — | — |
| `records` | `client_id = T and deleted_at is null` | — (RPC) | — (RPC) | — |
| `media` | `client_id = T` (deleted rows visible for "recently deleted") | — (RPC) | — (RPC) | — |
| `media_sets`, `media_set_items` | `client_id = T` | — (RPC) | — (RPC) | — (RPC) |
| `source_tokens`, `connector_schedule`, `connector_runs`, `notifications`, `raw*` | none | none | none | none |

Policies for `supabase_auth_admin` on `memberships` and `clients`: `using (true)` (hook reads).
Every policy is `to authenticated` — `anon` matches nothing.

Writes are all RPC (§3.3): the RPCs are `security definer`, owned by `postgres`, and set
`client_id := data.active_client_id()` themselves (R16). No dashboard statement ever inserts into a
`data` table directly, so no INSERT/UPDATE/DELETE policy is needed for `authenticated`.

### 2.5 Storage

Bucket `media`, private, `file_size_limit = 104857600` (100 MB, R20), `allowed_mime_types = null`
(any type; the upload RPC records the mime). Object key layout, all under the tenant prefix:

```
<client_id>/orig/<media_uuid>.<ext>      originals (uploads and Meta creative copies)
<client_id>/thumb/<media_uuid>.jpg       thumbnails, written only by the worker
```

Policies on `storage.objects` (`P1` = `(storage.foldername(name))[1]`, `P2` = `…[2]`):

```sql
-- read originals: tenant match AND budget not exceeded (R19, R22)
create policy media_read_orig on storage.objects for select to authenticated using (
  bucket_id = 'media' and P1 = (select data.active_client_id())::text and P2 = 'orig'
  and not (select data.egress_exceeded((select data.active_client_id()))));
-- read thumbnails: tenant match only, no budget (R21)
create policy media_read_thumb on storage.objects for select to authenticated using (
  bucket_id = 'media' and P1 = (select data.active_client_id())::text and P2 = 'thumb');
-- upload originals: tenant prefix, member/owner, orig folder only
create policy media_insert on storage.objects for insert to authenticated with check (
  bucket_id = 'media' and P1 = (select data.active_client_id())::text and P2 = 'orig'
  and data.jwt_client_role() in ('member','owner'));
-- no UPDATE/DELETE for authenticated: deletes are soft (RPC) and purged by the worker.
```
The dashboard uploads with `supabase.storage.from('media').upload('<client_id>/orig/<uuid>.<ext>', file)`
then calls `api.register_upload(path, …)`. Signed URLs come from
`createSignedUrl(path, 300)` after `api.download_url` (D9). Thumbnails are read with
`createSignedUrl` too (or `createSignedUrls` in batches of 100) — never public.

## 3. Schema `api` — the dashboard contract

### 3.1 Rules

- Every view: `create view api.<name>_v1 with (security_invoker = true) as …`; exposes
  `client_id`, `source`, `updated_at`; `grant select on api.<name>_v1 to authenticated`.
- Additive only. A column is never removed or retyped in `_v1`; breaking changes are `_v2`.
  CI `api_columns_additive` (§7) diffs `information_schema.columns` for `api` against the committed
  `api/contract.json` snapshot.
- Views expose `client_id` so the dashboard can cache-key by it; RLS guarantees it equals the
  caller's tenant.
- Money columns are `*_minor bigint` + `currency`. Ratios (`roas`, `conversion_rate`, `aov_minor`)
  are computed in views so every dashboard shows the same number.

### 3.2 Views

**`api.money_v1`** — every `data.money` column: `id, client_id, source, external_id, kind,
occurred_at, day, amount_minor, currency, status, order_number, customer_external_id, items_count,

**`api.daily_summary_v1`** — one row per `(client_id, day)`; the Overview / Shopify panel / DFR
source. `source = 'platform'`.
```sql
with days as (select client_id, day from data.money union select client_id, day from data.daily_metrics),
m as (select client_id, day,
        sum(amount_minor) filter (where kind = 'order')  as revenue_minor,
        count(*)          filter (where kind = 'order')  as orders,
        sum(amount_minor) filter (where kind = 'refund') as refunds_minor,
        sum(amount_minor) filter (where kind = 'payout') as payouts_minor,
        max(currency) as currency
      from data.money group by 1, 2),
d as (select client_id, day,
        sum(value) filter (where metric = 'sessions')                        as sessions,
        max(value) filter (where metric = 'conversion_rate')                 as conversion_rate_src,
        max(value) filter (where metric = 'inventory_units')                 as inventory_units,
        sum(value) filter (where metric = 'spend'          and source = 'meta') as ad_spend_minor,
        sum(value) filter (where metric = 'purchase_value' and source = 'meta') as ad_purchase_value_minor,
        sum(value) filter (where metric = 'impressions'    and source = 'meta') as ad_impressions,
        sum(value) filter (where metric = 'clicks'         and source = 'meta') as ad_clicks,
        sum(value) filter (where metric = 'purchases'      and source = 'meta') as ad_purchases
      from data.daily_metrics where entity_kind in ('store','campaign') group by 1, 2)
select days.client_id, 'platform'::data.source as source, days.day,
       coalesce(m.revenue_minor,0) as revenue_minor, coalesce(m.orders,0) as orders,
       coalesce(m.refunds_minor,0) as refunds_minor, coalesce(m.payouts_minor,0) as payouts_minor,
       m.currency,
       case when coalesce(m.orders,0) > 0 then m.revenue_minor / m.orders end as aov_minor,
       d.sessions, d.inventory_units,
       coalesce(d.conversion_rate_src,
                case when d.sessions > 0 then m.orders::numeric / d.sessions end) as conversion_rate,
       d.ad_spend_minor, d.ad_purchase_value_minor, d.ad_impressions, d.ad_clicks, d.ad_purchases,
       case when d.ad_spend_minor > 0 then d.ad_purchase_value_minor / d.ad_spend_minor end as roas,
       greatest(max(m_upd), max(d_upd)) as updated_at   -- max(updated_at) of contributing rows
from days left join m using (client_id, day) left join d using (client_id, day);
```
Only `campaign`-level Meta rows feed the totals (ad-level rows would double count).
`conversion_rate` prefers a source-reported value (`metric = 'conversion_rate'`) and falls back
to `orders ÷ sessions`; if neither exists it is null and the tile renders "—" (see §11).

### 3.3 RPCs

All: `language plpgsql security definer set search_path = ''`, owned by `postgres`,
`revoke execute … from public, anon; grant execute … to authenticated`. Each begins with
`tenant := data.active_client_id(); if tenant is null then raise … 'BCNS0'`. Input is validated
before any write. Errors use custom SQLSTATEs so the dashboard can branch on `error.code`:

| SQLSTATE | name | meaning |
|---|---|---|
| `BCNS0` | `no_tenant` | no active membership / claim |
| `BCNS1` | `budget_reached` | monthly egress quota exceeded (R22) |
| `BCNS2` | `forbidden_role` | needs `owner` |
| `BCNS3` | `validation` | bad argument (detail names the field) |
| `BCNS4` | `not_found` | id not in tenant |
| `BCNS5` | `too_large` | file > 100 MB or attributes > 256 KB |

PostgREST returns these as HTTP 400 with `{code, message, details, hint}`.

| RPC | Signature | Behaviour |
|---|---|---|
| `api.save_record` | `(kind text, attributes jsonb, external_id text default null, title text default null, body text default null, occurred_at timestamptz default now()) returns uuid` | Upsert into `records` with `source='dashboard'`, `client_id=tenant`, `external_id = coalesce(external_id, gen_random_uuid()::text)`, conflict on `(client_id, source, external_id)` → update `attributes, title, body, occurred_at, deleted_at = null`. Validates `kind ~ '^[a-z_]{1,64}$'`, `pg_column_size(attributes) <= 262144`. Returns `records.id`. (R17) |
| `api.delete_record` | `(record_id uuid) returns void` | Soft delete (`deleted_at = now()`) where `client_id = tenant and source = 'dashboard'`. |
| `api.register_upload` | `(path text, title text default null, tags text[] default '{}') returns uuid` | Requires `W`. Validates `path ~ ('^' || tenant || '/orig/[0-9a-f-]{36}\.[a-z0-9]{1,8}$')`. Reads `storage.objects` for `bucket_id='media' and name=path` → `BCNS4` if absent; `bytes = (metadata->>'size')::bigint`, `mime = metadata->>'mimetype'`; `BCNS5` if bytes > 104857600. Inserts `media(source='upload', external_id=path, storage_path=path, kind = case mime prefix image/→'image', video/→'video', else 'file', filename = coalesce(title, last path segment), tags = lowercased+deduped, uploaded_by = auth.uid())`. | `api.update_media_set` | `(set_id uuid, name text default null, description text default null) returns void` | `W`. |
| `api.delete_media_set` | `(set_id uuid) returns void` | `W`. Hard delete of the set and its items; media rows untouched. |

(`download_url`, `report_dashboard_version`) accept any role.

## 4. Connectors

### 4.1 Module contract (R24)

One TypeScript module per source in `worker/connectors/<source>.ts`:

```ts
export interface Connector {
  source: Source;                                       // 'shopify' | 'meta' | 'monday' | 'meet'
  defaults: { interval: string; backfillDepth: string;  // Postgres interval literals
              rateLimit: { concurrency: number; minDelayMs: number } };
  configSchema: ZodSchema;                              // shape of connector_schedule.config
  tokenKind: TokenKind;
  backfill(ctx: RunContext, from: Date, cursor: Json|null): AsyncIterable<Page>;
  incremental(ctx: RunContext, since: Json|null): AsyncIterable<Page>;   // since = incremental_cursor
  refreshToken?(ctx: RunContext): Promise<{ secret: string; expiresAt: Date }>;
  normalize(ctx: RunContext, rows: RawRow[]): CanonicalWrites;          // pure: raw → canonical
}
interface Page { raw: RawRow[]; cursor: Json; done: boolean }             // cursor persisted after each page
interface RawRow { entity: string; externalId: string; sourceUpdatedAt?: Date; payload: Json }
interface CanonicalWrites { money?: MoneyRow[]; products?: …; jobs?: …; messages?: …;
                            media?: MediaRow[]; dailyMetrics?: MetricRow[]; records?: RecordRow[];
                            customers?: …; tombstone?: { table: 'jobs'; keepExternalIds: string[] } }
```
`RunContext` gives the connector its token, `config`, `clients.timezone`, an HTTP client with the
source's rate limiter, and a logger. It has no scheduler, no DB handle, no Storage handle except
`ctx.putObject(path, bytes, mime)` for media copies. The worker (§5) drives the iterator, writes
raw, calls `normalize` on each page, upserts, persists the cursor.

Idempotency across all connectors: raw insert `on conflict do nothing`; canonical upsert on
`(client_id, source, external_id)` sets every mapped column (`attributes` replaced, not merged);
`daily_metrics` upsert on its PK sets `value`. Running the same page twice changes nothing (R7/R8).

## 5. Worker and jobs

### 5.1 Runtime

One Node 22 container, `worker/`, image built by GitHub Actions and deployed as **Cloud Run Job
`bcns-data-worker`** in the existing bcns GCP project. **Cloud Scheduler** `bcns-data-tick` runs
`*/5 * * * *` → `POST …/jobs/bcns-data-worker:run`. Job settings: 1 task, task timeout 600 s,
max retries 0, 1 vCPU / 1 GiB (sharp), overlapping executions **allowed** (leases make it safe).
Env: `DATABASE_URL` (Supabase pooler, session mode, IPv6-capable), `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `BCNS_ALERT_EMAIL`, `EGRESS_ALLOWANCE_BYTES`
(default 268435456000), `RUN_BUDGET_MS` (default 240000), `CLAIM_LIMIT` (default 8). The worker
talks to Postgres directly (`pg`), not through PostgREST; the service key is used only for Storage.

Entry `tick()` runs the steps below in order; each step is wrapped so a failure in one is logged
and the next still runs. Total wall clock ≤ 600 s; connector runs share `RUN_BUDGET_MS` each.

### 5.3 Claim and run (R25, R26, R28)

```sql
with due as (
  select s.client_id, s.source
  from data.connector_schedule s
  join data.clients c on c.id = s.client_id
  left join data.source_tokens t on (t.client_id, t.source) = (s.client_id, s.source)
  where s.enabled and c.status = 'active'
    and s.next_run_at <= now()
    and (s.lease_until is null or s.lease_until < now())
    and coalesce(t.status, 'active') = 'active'
  order by s.next_run_at
  limit $1                                    -- CLAIM_LIMIT
  for update of s skip locked)
update data.connector_schedule s
set lease_until = now() + interval '20 minutes', lease_owner = $2
from due where (s.client_id, s.source) = (due.client_id, due.source)
returning s.*;
```
Claimed rows run concurrently in-process, bounded by each connector's `rateLimit.concurrency`
(a per-source semaphore) so one client's backfill cannot starve another source, and by
`CLAIM_LIMIT` overall. Per claimed row:

1. `insert connector_runs (mode = backfill_cursor is not null ? 'backfill' : 'incremental', status 'running')`.
2. Load token + config; build `RunContext`.
3. Iterate `backfill(from, cursor)` or `incremental(since)`. Per page, in one transaction:
   insert raw (`on conflict do nothing`), `normalize`, upsert canonical, apply tombstone if
   present, `update connector_schedule set backfill_cursor|incremental_cursor = page.cursor`,
   bump `connector_runs.pages/rows_*`. Stop when `page.done` or `RUN_BUDGET_MS` elapsed.
4. Finish: `status='ok'`, `finished_at`. Schedule: if backfill finished → `backfill_cursor = null`,
   `next_run_at = now()` (first incremental follows immediately), notification
   `backfill_done:<client>:<source>`; if backfill still in progress → `next_run_at = now()`; else
   `next_run_at = now() + interval`. `last_success_at = now()`, `consecutive_failures = 0`,
   `lease_until = null`.
5. On error: `status = 'error'` (or `'auth_failed'` on HTTP 401/403, Meta code 190, Google
   `invalid_grant`, Shopify 401 → also `source_tokens.status = 'auth_failed'`, `status_detail`),
   `connector_schedule.last_error/last_error_at`, `consecutive_failures += 1`,
   `next_run_at = now() + least(interval, (2 ^ consecutive_failures) * interval '1 minute')`,
   lease cleared. Cursor stays where the last committed page left it.
6. Rate limits (HTTP 429 / Shopify `THROTTLED` / Meta code 4, 17, 32, 613): sleep per the
   connector's rule inside the budget; if the budget runs out, treat as a normal budget stop, not an
   error.

A run touches exactly one `(client_id, source)`; nothing it does blocks another row (R26). A tick
that finds nothing due exits in < 2 s.

### 5.4 Token refresh (R30)

`select … from data.source_tokens where status = 'active' and expires_at is not null and expires_at <
now() + interval '24 hours'` → for each, the connector's `refreshToken()`; success updates `secret,
expires_at, last_refreshed_at`; failure sets `status = 'auth_failed', status_detail`. Only
`google_oauth_refresh` has an `expires_at`; the others are skipped by the predicate.

### 5.5 Health (R32)

For every `connector_schedule` row, in one SQL statement, write `connector_health`:

| status | rule (evaluated in order) |
|---|---|
| `auth_failed` | `source_tokens.status = 'auth_failed'` or last finished run `status = 'auth_failed'` |
| `never_ran` | no run with `finished_at` |
| `error` | last finished run `status = 'error'` and `consecutive_failures >= 1` and not stale |
| `stale` | `last_success_at < now() − 2 * interval` (missed ≥ 2 runs), **or** last finished run `ok` with `rows_fetched = 0` while each of the previous 10 `ok` runs for that row had `rows_fetched > 0` |
| `ok` | otherwise |

`status_since` is kept from the previous row when the status is unchanged. `last_error` is
`connector_schedule.last_error` when status ∈ {error, auth_failed, stale}, else null.
Paused/churned clients keep their last row; `computeHealth` skips them.

### 5.8 Re-normalize (R7, R10)

Triggered by `connector_schedule.renormalize_requested_at is not null` (timezone change) or by

like a run (`mode = 'renormalize'`), reads raw newest-per-key
(`distinct on (client_id, source, entity, external_id) … order by …, source_updated_at desc nulls
last, fetched_at desc`) in batches of 1,000, calls `normalize`, upserts. Clears
`renormalize_requested_at` when the row's raw is exhausted. Only that client's rows are touched.

## 11. Needs Nate

Decisions this design could not make. Each blocks only the item named, not the build.

- **N1 — Conversion rate source.** The Shopify Admin API exposes no sessions or conversion
  metric on any plan; `shopifyqlQuery FROM sessions` is undocumented and is probed at onboarding
  (S4). If the probe fails, the tile shows "—". Options: (a) accept "—" and tell Declan (quote
  already hedges); (b) add a GA4 sessions connector (new source, ~1 day); (c) use Meta clicks as a
  proxy (wrong number, not recommended). Default in this design: (a).
- **N2 — Meta ad-account timezone.** Meta daily rows are bucketed in the ad account's timezone
  and cannot be re-bucketed. If SB's account is not `America/New_York`, ROAS-by-day will be off by
  the offset at day edges. Decide: accept, or ask Declan to confirm the account timezone before
  signing.
- **N3 — Meet connector is provisional.** No `fixtures/meet-sample.*`. The Drive listing and
  OAuth are designed; note parsing (title pattern, participants) waits on a sample from Declan.
- **N4 — Owner "add user".** Adding a user needs the Auth admin API (service key), so it stays a
  bcns script (D16). If SB expects self-serve invites, that is one edge function + RPC, not in
  this design.
